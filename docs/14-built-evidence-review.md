# Built evidence review

Date: 6 October 2026. This review revisits the research questions using only repository evidence that now exists: implementation, tests, checked-in bundles, benchmark results and CI configuration. It does not add market evidence, external product trials or claims about workflow runs that are not recorded in the repository.

## Resolved by the current build

| Earlier question or claim | Current answer | Repository evidence |

## Still unresolved by the build

The following questions require evidence that source code, tests and synthetic benchmarks cannot supply:

- **Recurring user pain and demand.** No interviews, independent task observations or repeat-use evidence answer whether target engineers have a recurring problem inadequately served today (`docs/10-sources-and-evidence.md:49`; `docs/09-validation-and-delivery.md:55-61`).
- **Comparative usefulness.** There is no counterbalanced study showing that Parison saves total task time without increasing false passes, and no hands-on competitor workflow comparison beyond the narrow engine compatibility spike (`docs/10-sources-and-evidence.md:48-50`).
- **Commercial viability.** There are no purchases, renewals, conversion, retention, acquisition-cost or support-cost observations. Pricing examples remain experiments rather than forecasts (`docs/03-market-and-monetization.md:29-47`; `docs/10-sources-and-evidence.md:54`).
- **AI-substitution resilience.** The repository does not contain a fair repeated-use benchmark against generated scripts or agent-built alternatives (`docs/10-sources-and-evidence.md:55`; `docs/08-ai-development-and-optional-ai.md:56-68`).
- **Million-row, raw-mode and out-of-core support.** The largest measured standard summary case is 250,000 rows. Raw mode retains both inputs and is not performance-qualified at those sizes; partitioning and spill-to-disk are not implemented (`docs/13-tested-support-envelope.md:24-30`).
- **Database and hosted workflows.** Connectors, snapshot guarantees, credential boundaries, multi-user authentication, authorization, retention and tenant isolation are deliberately unimplemented and remain separately gated (`docs/09-validation-and-delivery.md:63-73`; `docs/06-proposed-architecture.md:127-138`).
- **Full security assurance.** The build has useful regression tests, not a security assessment. Network isolation, malicious-file coverage, report/log canary coverage, resource-exhaustion behavior and offline installation/update behavior remain unverified (`docs/07-security-and-data-handling.md:1-7`, `docs/07-security-and-data-handling.md:58-64`).

## Current decision state

The repository evidence supports continuing with the contract-specific, local, file-first CLI under MIT. It supports an explicit alpha envelope: keyed scalar CSV/Parquet comparison, summary-mode performance up to the recorded shapes, bounded opt-in raw evidence and an agent-mediated review workflow. It does not support claims of market fit, superior direct-human usability, universal privacy, broad platform performance, million-row capacity or completed release readiness.

The agent-mediated unfamiliar-workflow gate is complete: two blinded agents independently reached the expected decisions on different recipes, and a human reviewer accepted the second recommendation and evidence. The preliminary alpha name screen and release-candidate verification are also complete. Direct-human CLI testing and comprehensive legal clearance remain useful follow-up work rather than hard blockers for the bounded alpha. Tagging and publication have not been performed.
