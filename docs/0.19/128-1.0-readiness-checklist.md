# Parison 1.0 readiness checklist

Status: **active gate**

Release 1.0 only when every required item below is checked with durable evidence. Passing automation is necessary but does not substitute for the human workflow gate or the maintainer's explicit release decision.

## Compatibility standard

- [x] The [compatibility contract](126-compatibility-contract.md) freezes released semantic and artifact surfaces.
- [x] The upgrade corpus covers keyed result schema 1, aggregate result schema 2, multiset result schema 3, suite-v1 and suite-v2.
- [x] Corpus tests pin top-level manifest digests and exercise recursive verification, safe inspection and Statement projection.
- [x] Built-wheel CI passes the corpus on Python 3.11–3.14, macOS and Windows at qualified checkpoint `0028e7c`.
- [ ] The final candidate introduces no undocumented compatibility exception.

## Complete migration workflow

- [x] One automated acceptance test covers `parison init`, record preflight, two rehearsals, catalog history and diff, suite execution, bundle verification, Statement verification and cutover reporting.
- [x] The acceptance test passes from checkpoint `0028e7c` wheels across the supported CI matrix.
- [x] A direct human who did not implement the workflow completed it without reported confusion or undocumented repository knowledge.
- [x] No confusion or failure was reported; therefore the rehearsal identified no corrective work to resolve or accept.

## CI and evidence handoff

- [x] CI builds the wheel before running installed-package acceptance.
- [x] Linux covers Python 3.11–3.14; macOS and Windows run installed-wheel smoke workflows.
- [x] Signing guidance distinguishes bundle integrity, signer authentication, policy approval and extraction truth.
- [x] Statement verification binds exact manifest bytes without performing cryptography or network access.
- [x] Checkpoint `0028e7c` passes ordinary CI and the identity-constrained signing workflow.

## Performance and limits

- [x] The [performance envelope](127-performance-envelope.md) consolidates keyed, aggregate, multiset and suite evidence without universal capacity claims.
- [x] Memory and SQLite measurements report accuracy, time, peak memory and temporary storage where applicable.
- [x] Processing limits remain explicit guards rather than capacity promises.
- [x] Targeted raw-sensitivity and repeated-concurrency evidence closes the actionable gaps; cross-platform throughput is explicitly accepted as deployment-specific.

## Product and documentation

- [x] Multiple realistic starter suites cover payout reconciliation, feature-pipeline parity and warehouse backfill.
- [x] Migration, dbt, Airflow, Dagster and generic CI integrations keep extraction and credentials outside Parison.
- [x] `docs/CURRENT.md`, the documentation index and README identify the active version and authoritative workflow.
- [x] The consolidated [0.19 user guide](131-user-guide.md) presents one primary migration/backfill path and the complete supported feature surface without requiring readers to assemble it from version history.
- [ ] The changelog describes every user-visible 1.0 guarantee and incompatibility.

## Candidate and release

- [ ] Set the exact candidate version and commit only after all preceding gates pass.
- [ ] Run `make check` and the active release checklist from a clean checkout.
- [ ] Merge the reviewed candidate to `main`; tag that exact merge.
- [ ] Build and publish wheel, source archive and checksums from the tagged commit.
- [ ] Re-download public assets, verify checksums and repeat direct and suite smoke workflows.
- [ ] Reconcile `docs/CURRENT.md`, `docs/README.md`, README, changelog and release records to the published artifacts.

Native workbook support and the other formats in [non-CSV input research](124-non-csv-input-research.md) are not 1.0 gates. Promote one only if concrete adoption evidence outweighs the new parser and compatibility surface.
